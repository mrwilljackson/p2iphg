# Airtable Import Specifications

**Version:** 1.0
**Date:** 2026-03-14
**Purpose:** Exact table and field setup required in Airtable so that the P2I Event CRM import works correctly.

---

## Overview

The app imports data from four Airtable tables in a specific order:

1. **Events** → imported first (everything else links to an event)
2. **Organisations** → imported second
3. **Organisation_contacts** → imported third (links orgs to events)
4. **Volunteers** → imported last (links to events)

Each table must use the **exact table name** and **exact field names** listed below. Airtable field names are case-sensitive.

---

## 1. Events Table

**Airtable Table Name:** `Events`

| Field Name | Field Type | Required | Notes |
|---|---|---|---|
| `Event Name` | Single line text | ✅ Yes | Display name of the event |
| `Event Date` | Date | ✅ Yes | Format: `YYYY-MM-DD`. Only future events are shown for import |
| `Location` | Single line text | Optional | Venue / address |
| `Description` | Long text | Optional | Event description |
| `Status` | Single select | Optional | Options: `planned`, `active`, `completed`. Defaults to `planned` if blank |

> **Tip:** The Airtable Record ID (auto-generated by Airtable, e.g. `recXXXXXXXXXX`) is stored as the link between all tables. You never need to create this — Airtable provides it automatically.

---

## 2. Organisations Table

**Airtable Table Name:** `Organisations` (UK spelling)

| Field Name | Field Type | Required | Notes |
|---|---|---|---|
| `Organisation Name` | Single line text | ✅ Yes | Name of the organisation. Can also be a lookup field from another table (the app handles both string and array values) |
| `Organisation Name Text` | Formula / Single line text | Optional | If `Organisation Name` is a lookup (returns array), add this as a formula field with the plain text name. The app uses this as a fallback |
| `Type` | Single select | ✅ Yes | See **Organisation Type Values** below |
| `Event` | Link to another record (Events) | Optional | Links to the Events table. Used as a fallback for event matching |
| `airtable_event_id` | Single line text OR Link to record | ✅ Recommended | The Airtable Record ID of the event (e.g. `recABC123`). This is the **preferred** field for linking orgs to events. Can be a text field containing the ID, or a linked record field |
| `Expected Group Size` | Number (integer) | Optional | Expected number of participants from this organisation |
| `Contact First Name` | Single line text | Optional | Primary contact first name |
| `Contact Last Name` | Single line text | Optional | Primary contact surname |
| `Contact Email` | Email | Optional | Primary contact email |
| `Contact Phone` | Phone number | Optional | Primary contact phone |
| `Notes` | Long text | Optional | Free-text notes |

The `Type` field must use one of the following values. The app normalises these 18 Airtable types into 7 internal categories:

| Airtable `Type` Value | → App Category | Registration Form Visibility |
|---|---|---|
| `Family` | Family | **Group role only** |
| `Disability` | Disability | **Group role only** |
| `Business` | Corporate | Participant role only |
| `Corporate Partner` | Corporate | Participant role only |
| `Sports Body` | Sporting | Participant role only |
| `Sports Club` | Sporting | Participant role only |
| `Competitor` | Sporting | Participant role only |
| `Community Group` | Community | Participant role only |
| `Social Groups and Events` | Community | Participant role only |
| `Education Body` | Educational | Participant role only |
| `Charity` | Other | Participant role only |
| `Estate Agents` | Other | Participant role only |
| `Funder` | Other | Participant role only |
| `Government` | Other | Participant role only |
| `Health` | Other | Participant role only |
| `HR` | Other | Participant role only |
| `Media and News` | Other | Participant role only |
| `Supplier` | Other | Participant role only |

> **Important:** If `Type` is blank or contains an unrecognised value, it defaults to `Other`. Getting this field right is critical — it determines which organisations appear in the Participant vs Group registration dropdowns.

## 3. Organisation Contacts Table

**Airtable Table Name:** `Organisation_contacts` (note the underscore)

This table links organisations to specific events and holds per-event contact details.

| Field Name | Field Type | Required | Notes |
|---|---|---|---|
| `Organisation ID` | Link to another record (Organisations) | ✅ Yes | Links to the Organisations table. The app reads the linked record's Airtable Record ID to cross-reference |
| `Organisation Name (from Organisation ID)` | Lookup | Optional | Auto-populated lookup showing the org name. Used for display only |
| `airtable_event_id` | Link to another record (Events) | ✅ Yes | Links to the Events table. The app reads the first linked record ID to match to the correct event |
| `Type` | Single select | Optional | Same values as the Organisations `Type` field. Maps to `groupType` in the database |
| `Contact First Name` | Single line text | Optional | Event-specific contact first name |
| `Contact Last Name` | Single line text | Optional | Event-specific contact surname |
| `Contact Email` | Email | Optional | Event-specific contact email |
| `Expected Group Size` | Number (integer) | Optional | Expected participants for this event |

---

## 4. Volunteers Table

**Airtable Table Name:** `Volunteers`

| Field Name | Field Type | Required | Notes |
|---|---|---|---|
| `Event Name` | Link to another record (Events) | ✅ Yes | Links to the Events table. The app reads the first linked record ID to match to the event |
| `Email` | Email | ✅ Yes | Volunteer's email — used as the unique identifier during registration |
| `First Name` | Single line text | ✅ Yes | Volunteer's first name |
| `Last Name` | Single line text | ✅ Yes | Volunteer's surname |
| `Photo Consent` | Checkbox | Optional | Defaults to `false` if unchecked |
| `Feedback Consent` | Checkbox | Optional | Defaults to `false` if unchecked |
| `Next Event Consent` | Checkbox | Optional | Defaults to `false` if unchecked |

> **Note:** During registration, volunteers must enter an email that matches a pre-imported volunteer record. If no match is found, they cannot register as a volunteer.

## Import Order (Critical)

You **must** import in this order via the P2I Admin Dashboard:

```
1. Events          ← must exist first (everything references events)
2. Organisations   ← must exist before contacts can link to them
3. Organisation    ← links orgs to events; creates org_contacts rows
   Contacts
4. Volunteers      ← links to events via "Event Name" linked record
```

If you import out of order, records will fail to link and you'll see "Unknown Event" or null references.

---

## How Linking Works

All cross-table linking relies on **Airtable Record IDs** (the `rec...` identifiers auto-generated by Airtable). You don't create these manually — they're assigned when you create a record.

- **Events** → each event gets a Record ID (e.g. `recABC123`)
- **Organisations** → the `airtable_event_id` field should contain or link to the event's Record ID
- **Organisation Contacts** → `Organisation ID` links to the org's Record ID; `airtable_event_id` links to the event's Record ID
- **Volunteers** → `Event Name` links to the event's Record ID

When you use Airtable's "Link to another record" field type, these IDs are handled automatically. If you use a plain text field for `airtable_event_id`, you must paste the event's Record ID manually.

## Common Pitfalls

| Problem | Cause | Fix |
|---|---|---|
| Organisations don't appear in dropdown | `Type` field is blank or misspelt | Set a valid `Type` value from the list above |
| Orgs appear in wrong role dropdown | `Type` is e.g. `Family` but expected in Participant | `Family` and `Disability` types only show for Group role — this is by design |
| "Unknown Event" after import | `airtable_event_id` doesn't match any imported event | Import events first, then check the event's Record ID matches |
| Volunteer can't register | Email doesn't match any imported volunteer | Check the `Email` field in Airtable matches exactly (case-insensitive) |
| Organisation name shows as array | `Organisation Name` is a lookup field returning `["Name"]` | Add an `Organisation Name Text` formula field with the plain text value |
| Contacts not linked to event | `airtable_event_id` field missing in Organisation_contacts | Add the linked record field pointing to Events |

## Environment Variables

The app needs these environment variables to connect to Airtable:

```
AIRTABLE_API_KEY=pat...        # Personal Access Token from airtable.com/create/tokens
AIRTABLE_BASE_ID=app...        # Found in the Airtable URL: airtable.com/{BASE_ID}/...
```
